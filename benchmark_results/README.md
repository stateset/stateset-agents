# Phase 0 Benchmark Results

This directory holds the empirical evidence that backs the v1.0 whitepaper revision. Every file under `whitepaper_v1/` is a single benchmark run's JSON output, schema-conformant to [`SCHEMA.md`](./SCHEMA.md).

## How to produce a result

**Recommended (Colab, ~$0.50, ~45 min on A100):**

Open [`notebooks/whitepaper_v1_gsm8k_benchmark.ipynb`](../notebooks/whitepaper_v1_gsm8k_benchmark.ipynb) in Google Colab, set runtime to A100, and run all cells. Drop the resulting JSON into `whitepaper_v1/`.

**CLI (local A100 / H100):**

```bash
# Smoke test the pipeline (no GPU, ~6 s)
make benchmark-smoke

# Single configuration
make benchmark-phase0 TRAINER=gspo SEED=42

# Full 9-run matrix (3 trainers × 3 seeds, ~6 hours on A100)
make benchmark-phase0-all
```

## How to publish

```bash
# Aggregate into summary.md, summary.csv, and a pass/fail gate report
make benchmark-aggregate

# Or, in CI, fail on any gate violation:
make benchmark-aggregate-strict
```

The generated `summary.md` is the table that goes into §11.7 of the whitepaper.

## Publication gates

A (trainer, model) group passes only if:

- ≥3 seeds (variance bars are non-negotiable)
- Standard deviation of `eval_pass_at_1` ≤ 0.10 (results are not noise)
- Improvement over baseline ≥ +0.030 (the framework actually does something)
- All runs share a single git commit (no apples-to-oranges)

See [`SCHEMA.md`](./SCHEMA.md) for the full JSON schema and gate definitions.

## What gets published in the whitepaper

The aggregated `summary.md` (auto-generated) lands verbatim in §11.7. Every claim in v1.0 with a numeric value has a corresponding W&B run URL that traces back to one of the JSON files here.
